# 0045 — Recording: screen and face as separate files, and an input log

Date: 2026-10-19 · Decided by: AJ ("i want to have a recording funtionality in this app. facecam and screen recording as seperate files and also my cursor position and focused field position logged every frame"; hide and redraw the cursor, mic as a track in the face file, one or several displays, every permission asked when the setting is turned on) · Status: adopted

## Context
gmclip edits screen + face recordings made elsewhere (OBS), and §1.4 lists recording as a non-goal. Follow the cursor (decision 0016) has to find the cursor in the picture: an arrow template on decoded master frames, 19–45 s for a 55 s render, no I-beam or hand, and a cursor baked into the pixels blurs when a crop zooms in. A recorder that knows where the cursor and the focused field are, on the same clock as the picture, makes cursor follow exact and cheap, lets zooms aim at what is being typed into, and lets the cursor be drawn at any size.

## Decision
- **Recording leaves §1.4** and is §5.18. It is a backlog item, not a MUST: no gate gives anything up for it.
- **Setting.** Settings → Recording, off by default. Turning it on asks, in order, for Screen Recording, Camera, Microphone, Accessibility and Input Monitoring, and shows each one's state. With it off there is no Record button. A permission refused later turns off only what needs it, and the session says what is missing (§1.5 principle 5).
- **One clock.** Every frame, sample and event is stamped in host time (`mach_absolute_time`, which ScreenCaptureKit, AVCapture and CGEvent all use) and stored as µs from the session's `t0`. The files of a session are a sync group with offset 0 when added (decision 0018); no envelope matching.
- **Session folder** `Recording <date time>/` (in `~/Movies/gmclip/Recordings` from the app): `session.json` (`gmclip.rec/1`: each screen file's display with origin, size in points and pixels, scale, frames and drops; the face file's camera and mic; app version; permissions in force; what is missing; length; `complete`), `screen-<display id>.mov` (or `screen-window-<id>.mov`) per screen, `face.mov`, `events.ndjson`, `cursors/<sha256>.png`.
- **Screen.** ScreenCaptureKit, one display, several displays (one file each) or one window; native pixels; **`showsCursor = false`**; system audio as the first screen file's audio track. **30 fps by default, 60 opt-in**: on the dev M1 Pro the hardware HEVC encoder keeps up with 5K + 4K at 30 (0 of 250 frames dropped) but not at 60 (≈ 40 % dropped); the cursor is drawn from the log at the output rate either way. **Constant frame rate**: ScreenCaptureKit sends a picture only when the screen changed, so every slot `t0 + k/fps` is written with the latest picture, re-stamped (`CMSampleBufferCreateCopyWithNewTiming`), as the editor's frame-exact pipeline expects. Written with AVAssetWriter as **H.264** (gmclip decodes H.264 and VP9 today, HEVC from M2; a picture over 4096 a side or 4096×2304 pixels is scaled down keeping its aspect, so a 5K display records at 4096×2304 and the log maps to the file's pixels; `--hevc` keeps full 5K for later), fragmented every 1 s so a crash loses at most a second, then **finalized at stop** by an AVFoundation passthrough export (a stream copy) into a plain movie, since gmclip's demuxer refuses fragmented files (a crash leaves them fragmented; opening the session finalizes them).
- **Face.** AVCaptureSession: camera at its native mode, **mic as the second track of `face.mov`** (no separate WAV). The import sheet's "Which track is your mic?" is pre-answered.
- **Input log** (`events.ndjson`, one JSON object per line, `t` in µs):
  - `cursor`: global point and display, sampled on every captured screen frame, plus every move, drag, click (button, down/up, count) and scroll from a listen-only CGEventTap.
  - `cursor_shape`: on change, the system cursor's image (largest rep) stored once under `cursors/` with its hotspot; the event names its hash.
  - `focus`: the focused element (AX system-wide `kAXFocusedUIElement`): frame, role, subrole, app bundle id, window frame, and the caret rect (`AXBoundsForRange` on the selected range) when there is one. Polled at 15 Hz and logged on change (AX notifications are per-app observers; polling covers every app the same way). Chromium and Electron apps get `AXManualAccessibility` set so they expose their tree.
  - `keys`: key-down counts per poll (66 ms), **never characters**; the event tap sees key codes only to spot the hotkeys (⌃⌥S stops, ⌃⌥M drops a marker, from any app). Secure text fields (`AXSecureTextField`) produce no focus caret and no key counts.
  - `app`: frontmost app and window changes. `marker`: the marker hotkey.
- **Import.** The face file (the voice) and the first screen file are one recording at offset 0 (the app's `open_recording`, no sound matching); any other display is a video of its own. Each screen file's raw events become an `InputTrack` (`gmclip-model::rec`, `gmclip.input/1`: that file's pixels, µs from its first frame; a window recording maps through the window's frame over time), stored as an asset (`application/vnd.gmclip.input+json`, `<sha256>.json`) with its cursor PNGs, and attached by `source_cursor_set`, which also restyles it (visible, scale, smoothing, hide when idle, click rings).
- **Code.** Capture FFI in `gmclip-gpu::apple::capture` (the crate allowed `unsafe`, through the Objective-C runtime and C APIs as `share.rs` does; `block2` became a direct dependency, already in the tree); the session, its log and the track conversion in `gmclip-media::rec`; `gmclip record start|sources|permissions|probe|tracks` in the CLI; `recording_*` in the app.
- **Redraw.** The cursor is a layer the compositor draws from the log (image, hotspot, scale, optional smoothing, click emphasis, hide when idle), in `frame_draw`, so preview and export match (R-COMP-1). `cursor_follow` and a new zoom-to-focus pass read the log instead of the pixels and write eased splits as in 0016; both are MCP tools. Sources without a log keep 0016's detector.
- **Order:** R0 `gmclip record` (screen + cursor log) → R1 face + mic, one-frame sync check → R2 focus and caret → R3 app UI (setting, source picker, countdown, menu-bar stop, hotkeys) → R4 import the session, cursor layer, cursor follow from the log → R5 zoom to focus and clicks.

## Evidence
- R0 on AJ's Mac (two displays, 5120×2880 and 2160×3840, `gmclip record start --all-displays --no-face --duration 4`, then HEVC): two HEVC files, 123 and 127 frames over 4.03 s at 30 fps with 0 dropped; a cursor sample per frame, the cursor shape stored once, the focused element and the frontmost app logged; after finalizing, gmclip's own MP4/MOV demuxer indexes both (the system sound's edit list starts 12 ms after `t0`, as recorded). Unit tests: `gmclip-model` `rec::tests` (interpolation, gaps, off-picture, focus/clicks, `check`), `gmclip-media` `rec::convert::tests::a_second_display_maps_global_points_to_its_pixels` and `a_window_recording_follows_the_window`, `rec::tests::events_round_trip_and_a_torn_last_line_is_skipped`; `gmclip-core/tests/source_cursor.rs::a_recorded_cursor_is_attached_then_restyled_and_undone`.
- Import end to end: `app/src-tauri/tests/recording.rs::a_recording_opens_with_its_cursor_attached` (lab, `GMCLIP_LAB_REC=<session>`) on that session: a project whose two screen sources carry `cursor` (a valid `gmclip.input/1` track asset and the cursor PNG with its size), and a `/1` plan with a `cursors[]` entry per source. Rendering a frame of it failed on the HEVC decode gate, which is why recordings are H.264. `gmclip-gpu` `capture::screen::tests::h264_pictures_fit_the_encoder`.
- Not yet measured: an H.264 take end to end (the displays were unavailable to ScreenCaptureKit for the rest of the session, a locked screen), a frame rendered with the redrawn cursor from a real recording, the 5-minute take against a cursor-visible reference capture (within 2 px), and R1's clap across `screen` and `face` within one frame (the camera permission had not been granted on the dev Mac).
- R4/R5 (follow and zoom from the log): `gmclip-core` `zoom` unit tests (`typing_in_a_field_zooms_on_the_caret_then_out_when_idle`: a 2× key on the caret with the first key, out 2.5 s after the last; `a_field_without_a_caret_is_zoomed_only_as_far_as_it_fits`; `keys_outside_a_text_element_do_not_zoom`; `a_click_is_held_then_zoomed_out`; `a_click_after_typing_moves_on_from_the_caret`; `moves_are_at_least_a_second_apart_and_inside_the_base`; `caret_moves_inside_the_middle_hold_the_crop`; `a_group_part_reads_its_picture_member_at_its_offset`: member time = group time − offset). `gmclip-mcp/tests/media_tools.rs::follow_and_zoom_from_the_input_log_are_agent_reachable`: `crop_follow_cursor` on a source with `cursor` reports `method: "input_log"`, places the cursor in 4/4 samples and decodes no frames; `crop_zoom_focus` previews a caret key then a click key and applies as one `cursor_follow_apply` transaction; a source without a log is refused. `follow_the_cursor_is_agent_reachable` now checks `method: "pixels"` without a log.
- R4 (cursor redraw): RenderPlan `/1` `cursors[] {id, source, path, sha256, shapes: [images[].id by shape index], scale, smooth_ms?, hide_idle_ms?, clicks?}` and `parts[].layers[].cursor` (a `cursors[].id` of the layer's picture source); `render_sig` appends each track's sha256 after the images'. `gmclip-plan/tests/v1.rs::recorded_cursors` (parses and round-trips under `/1`, refused under `/0`, every reference, the source match, bounds and duplicate ids); `gmclip-media` `export_record::tests::a_cursor_track_file_signs` (the track's file signs, its path does not); `gmclip-core/tests/recorded_cursor.rs::a_recorded_cursor_plans_once_per_source_under_v1` (one entry per source named by every layer, images at the host's files, a hidden or absent cursor plans `/0` as before). `gmclip-render` `compositor::cursor` draws it in the one compose: `tests/recorded_cursor.rs::the_cursor_moves_and_scales_with_the_crop` (a 2× tighter crop draws it 2× larger and moved with the picture, clipped to the place, CPU pixels), `an_idle_cursor_fades_and_a_bad_track_draws_nothing` (idle fade, click ring, a missing or malformed track is a note), `the_shared_compose_draws_the_cursor` (macOS, Metal: `render_frames`, the preview's and export's compose, puts it on the pixels the CPU path predicts).
