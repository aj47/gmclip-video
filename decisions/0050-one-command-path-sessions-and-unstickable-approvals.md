# 0050 — One command path for the window and agents, sessions, and approvals that don't stall everyone

Date: 2026-10-26 · Decided by: agent (go from AJ on 2026-10-26: "one set of commands behind both the UI and agents, with undoable runs") · Status: adopted

## Context
Agents in AJ's terminal threads script MCP through a helper that starts `gmclip-app mcp` per call, so every call was a new connection and every edit its own run. App commands (decision 0038) ran as the human with no `base`: an agent's `hook_set` then `export_start` skipped R-LINT-2's gate (only the `export` tool applied it), those edits escaped `run_undo`, and `job_wait`/`verify` could not see the app's exports.

## Decision
- **App commands are the agent's calls.** `AppHost::call` takes the caller; the app runs the command with every registry call it makes on that thread as the agent (`core::acting_as`), with `base: {as_of: now}`. Its edits land in the agent's run and History names the agent. A full-access run's project-wide commands (decision 0043) are not held to its cut there; the holder already keeps them on its own project. `source_import` imports as the agent too.
- **R-LINT-2 for app exports.** `export_start`, `export_both` and `opening_export` from an agent need `render` and meet the `export` tool's gate (`NeedsApproval` with what blocks it). Hooks with an unbacked digit that exported through `export_start` before are refused now, as intended. Invented numbers stay blocked; no terms exemption.
- **One job view.** An app export an agent started is its job: `job_wait` waits on it and `verify` checks its file against the plan it rendered (`AppHost::job`). Other identities get `NotFound`.
- **Sessions.** An agent names its session with `GMCLIP_SESSION=<label>` (1–64 letters, digits, `.`, `_`, `-`) in the environment of `gmclip mcp` / `gmclip-app mcp`; the shim sends it in the handshake (`ClientHello.session`, only when set). Every connection naming it is one identity, `local:session-<label>`, with one run (the actor's run key `session:<label>`), which outlives each connection and ends idle (15 min) or with `run_end`. The label is not a credential: it widens no scope (the outside agent's scopes), is ignored when a launched run proves its credential, and a malformed one is refused at the handshake. Any process of the user can name any label, as it can name any client today.
- **`gmclip-app call <tool|command> '<json>'`**: one tool call over a fresh connection in the same session, the result's JSON on stdout, exit 1 on an error. A tool name takes the JSON as its arguments; any other name runs as `command_run`, with `project`, `base` and `request_id` lifted out of the JSON.
- **Approvals per run (R-PROTO-6).** An approval belongs to the run it was asked in (`Conn::run_key`: launched run, session, or the connection); the 4th pauses that run only, so a child thread's refused exports no longer freeze its siblings and parent. The same ask again while it waits (same tool, cut revision and findings), from that run or any connection of the same agent, returns that approval's id and does not count. `export{dry_run: true}` reports `blocked`/`blocked_by` and never asks. A paused run gets `Paused{pending, resume}` ("This agent keeps asking — review run" and where the human resumes it) instead of `Busy`; "Pause agents" answers `Paused` too (§11.6 always said so). `CmdError::Paused` gains `pending` and `resume` (both defaulted, so a bare `{"code": "Paused"}` still reads).
- **Where the human sees asks.** Pending asks are on Home's "Needs you" (who asked, what blocks it, the cut's own title) and counted in the top bar's agents badge; both refresh when an ask arrives or goes. An export ask carries the export the agent asked for (`effects.export`). "Approve and export" (Home and the activity rail) runs it as the human, which R-LINT-2 always allowed, only while the cut is as it was when the agent asked (else `Conflict`: look again); the job is then the agent's to `job_wait`/`verify`. "Done" is now "Dismiss" (it only ever dismissed).
- **Undo this agent.** In History, a version taken before an agent's run has "Undo this agent": `run_undo` of that run as the human, one undo step. When later edits touched the same things, it shows the core's `Conflict` choices on that row: "Undo only what nobody changed since" (`revert_untouched`), "Put it all back as before the agent" (`restore_to_point`), Cancel.
- **A truthful surface.** `export` says it renders, that lint errors refuse it with one ask and that `dry_run` checks first; `lint` says its errors block exports; `analysis_get` says prosody and the visual kinds are not built (`Unsupported`; use `see`). The server instructions add the session label, `run_end`/`run_undo{run}`, `run_summary_set`, the number rule (a matching measurement or the spoken word; a note is not provenance; no respelling) and the export gate. The app's Claude Code line is `claude mcp add --scope user gmclip -- <exe> mcp`, as R-MCP-2 says. A client refusing a socket served by another executable names it and the line to run instead (`'<that exe>' mcp`).

## Evidence
- `crates/gmclip-mcp/tests/app_commands.rs::an_app_command_is_the_agents_own_call`: the hook is in the agent's run and `run_undo` takes it back; `export_start` is refused before the app sees it; `job_wait` and `verify` find the app's job; another agent does not.
- `app/src-tauri/tests/agent_calls.rs`: the real app command (`hook_set`) writes in the agent's run and `run_undo` takes it back while the window's own call stays the human's; `export_start` through the holder returns `NeedsApproval` (`number_without_provenance`).
- `crates/gmclip-mcp/tests/agent_sessions.rs`: a connection, then two `gmclip call`s, then a connection under another client name, all of session `thread-a`, make one run of two transactions that a sibling session cannot undo; malformed labels are refused; a session's tools are an outside agent's; a launched run's proof wins over a label.

- `crates/gmclip-mcp/tests/media_tools.rs::a_fourth_approval_pauses_that_run_only`: three identical refusals are one ask, a dry run asks nothing, the 4th distinct ask returns `Paused{pending: 3, resume}`, and another connection of the same client goes on. `agent_surface.rs::paused_agents_are_refused_until_resumed`: "Pause agents" answers `Paused`. `gmclip-proto`'s `paused_says_where_to_resume`.
- `app/src-tauri/tests/agent_calls.rs::a_refused_export_waits_on_home_and_the_human_exports_it`: the ask is on Home with the cut's title; a cut changed since is not exported; approved, it exports as the human, leaves Home and is the agent's job.
- `app/ui/tests/e2e/agent-asks.spec.ts` (h79): a session's `hook_set` + `export_start` twice is one ask, on Home with the badge at 1; "Approve and export" clears both and exports; the agent's `job_wait` sees it done. `approvals.spec.ts`: the same ask again counts once.
- `agent_surface.rs::the_surface_says_what_it_does` and `::a_wrong_server_names_the_binary_to_run`; `app/src-tauri/tests/agent_calls.rs::the_claude_code_line_adds_gmclip_for_every_folder`; `agent-buttons.spec.ts` expects the user-scope line.
- `app/ui/tests/e2e/agent-undo.spec.ts`: a session retitles the cut and writes a note; you write over the note; "Undo this agent" offers the choices, and "Undo only what nobody changed since" restores the title and keeps your note.
