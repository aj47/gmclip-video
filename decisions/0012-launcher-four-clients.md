# 0012 — The launcher runs any of the user's agents: Claude Code, Codex, pi, opencode

Date: 2026-10-15 · Decided by: agent (lane G, per AJ's direction; decision 0002 defaults) · Status: adopted

## Context
AJ: "i should be able to use any agent that i have with their sub i.e claude / codex / pi / opencode". The launcher (R-AGT-1..5, decision 0007) knew Claude Code and Codex only. pi 0.85.1 (`/opt/homebrew/bin/pi`, a `#!/usr/bin/env node` bundle) and opencode 1.18 (`/opt/homebrew/bin/opencode`, native) are installed on AJ's Mac. Their flags were read from `--help`, pi's shipped docs (`docs/usage.md`, `security.md`, `extensions.md`, `json.md`) and the strings of both binaries; neither was run beyond `--version`/`--help` (no model turn, no S7 run).

## Decision
- **One launcher, four clients** (`gmclip_ai::launcher::clients`). Each runs headless on the user's own plan login, with only the run's enumerated gmclip tools and its per-run files in the run's `config/`; gmclip never writes `~/.claude`, `~/.codex`, `~/.pi` or `~/.config/opencode`.
  - **pi**: `<abs node> <abs pi script> -p --mode json --offline --no-extensions -e <run>/config/gmclip-pi.mjs --no-skills --no-prompt-templates --no-themes --no-context-files --no-approve --no-tools --tools <mcp__gmclip__… list> --system-prompt <file> --append-system-prompt <file> --session-dir <run>/config/pi-sessions --thinking <e> [--model]`. pi has no MCP client, so gmclip writes its own bridge extension (`pi_gmclip.mjs`) that starts `gmclip mcp` and registers exactly the run's tools. The given prompt files mean pi reads neither `~/.pi/agent/SYSTEM.md` nor `APPEND_SYSTEM.md` (checked in pi's code). The script runs under the `node` beside where pi was found, by absolute path, never `env`'s pick; no node beside it, no run. Login: `~/.pi/agent/auth.json`, read in place (`PI_CODING_AGENT_DIR` inherited only when set).
  - **opencode**: `<abs opencode> run --format json --pure --dir <cwd> [--model m --variant e]`, never `--auto`. Config in `OPENCODE_CONFIG=<run>/config/opencode.json`: gmclip the only MCP server; `permission: {"*": "deny", "gmclip_<tool>": "allow", …}` (the deny-all default is opencode's `--tools ""`; every allow is an exact name, R-AGT-4); share and autoupdate off. `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` and `OPENCODE_DB` point into the run; `OPENCODE_DISABLE_CLAUDE_CODE` (no `~/.claude/CLAUDE.md` or skills), `…_EXTERNAL_SKILLS`, `…_PROJECT_CONFIG`, `…_DEFAULT_PLUGINS`, `…_AUTOUPDATE`, `…_SHARE`, `…_LSP_DOWNLOAD`, `OPENCODE_PURE` set. Login: `XDG_DATA_HOME/opencode/auth.json` read in place; opencode still writes its log files under that data folder.
  - Claude Code and Codex keep decision 0007's sets unchanged.
- ~~**Unconfined → refused.** A client version with a known S7 leak is *unconfined* and refused for every launched run, whatever the version policy (only the S7 probe starts one). Today that is Codex 0.160.x (S7-X1 `$CODEX_HOME/AGENTS.md`, S7-X5 collaboration tools). Its fix is still AJ's Needs-AJ item 1.6.~~ Superseded by the 2026-10-16 amendment below.
- **Version gate.** pi and opencode have no S7-tested version (`version::supported` is `None`), so the gate refuses them under `Enforce` and they run only under `Verified{sha256}` for one exact build. The app's probe does not cover them yet (G.06), so "Run anyway" on the Owner sheet is the only way to that, as for a Claude Code build that failed its probe. For pi the hashed file is the bundle's entry script, whose imports are content-hashed chunk names.
- **Instruction files.** The cwd-ancestry check also refuses `.pi`, `.opencode`, `opencode.json[c]` and `CONTEXT.md`.
- **Continue a run** (G.03). pi and opencode resume their own session from a copy of the previous run's session files (pi: the session file by path, opencode: its database) in the new run's folder. Claude Code (sessions live in `~/.claude`) and Codex (`--ephemeral`) start a fresh run with the previous summary as an `<previous_run_summary untrusted="true">` block. Either way it is a new run: new credential, registration, restore point, same scopes.
