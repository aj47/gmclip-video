# 0039 — Full-access sessions reach the human's files; the library opens by name

Date: 2026-10-18 · Decided by: agent (AJ: "debug it, fix it", after a "Full access, no asking" session could not add his three Movies videos) · Status: adopted

## Context
AJ started a Claude Code session on the library with "Full access, no asking" and asked for a project from `~/Downloads/BB IDE Assets/` and three videos in `~/Movies`. The agent found every file with its own shell and made the project with `project_new` (decision 0038), then every gmclip call that touched a file failed: `videos_add` and `videos_open` (`file_roots`: no Owner roots on a fresh install, so only open projects' homes were readable), `project_open`/`project_open_home` on a home in gmclip's own library (`file_roots`), `project_open {path: "bb-mobile2.gmclip"}` (absolute path required), and `library_search` ("constraint failed"). It gave up and asked AJ to click. Session: `<app_data>/agent-sessions/s1792382433101-0.json`.

## Decision
- **gmclip's library is readable.** The homes in the library folder (real `*.gmclip` directories directly in it; a symlink there is not followed) are agent read roots for every agent, like open projects' homes. `project_open {path}` and any app command's path argument take the **name or id** of a library (or open) project instead of a home path (its name, its folder's name with or without `.gmclip`, case aside; several with one name → give the id). `project_list` adds `library: [{id, name (untrusted), home}]`.
- **A session grant for full access.** When the human starts a session with `full` or `bypass` on the library, a project or a video, the app registers a grant in-process (`Holder::grant_register`; nothing on the socket can) for the **human's home folder**, 8 h at most, and passes `GMCLIP_RUN=<grant>:<credential>` to the session's gmclip shim, which proves it in the handshake like a launched run (HMAC, single-use client nonce). That connection's file checks add the grant's folders to the read roots; scopes, identity (`local:<client>`) and implicit runs are unchanged. The grant ends with the session (a live connection is back to the read roots on its next call). Not for gmclip-only sessions, outside agents, or a cut's session (its launched run stays bound to the cut and gets no app commands). The launch sheet's full-access notes say "gmclip's tools may open files in your home folder for it". Why automatic: the human already gave that agent its own shell and files; refusing the same files through gmclip only made it fail.
- **A refusal teaches.** A `file_roots` refusal keeps its error code and adds `help: {readable, how}`: the Owner's roots, the grant's folders, open homes and the library, and how the human adds one (Settings → Agent access… → Folders agents may read, or a full-access session). The refused path is never echoed (R-FS-1). The session's first message names which files gmclip may open for it.
- **The library index heals.** AJ's index had 420 full-text rows past its last line (ids 1093–1512), so the next line's id met one and every refresh failed with fts5's "constraint failed". When the full-text and line counts differ, the transcript tables are emptied and re-read (the index is a cache), and a line's full-text row is written with `INSERT OR REPLACE`. How the rows were orphaned is not known; the index now recovers either way.
- **A transcript stored twice is not a failure.** The app transcribes a video when it is added, and an agent's `transcript_read` can start the holder's own job for the same source; both reach the same revision with slightly different words, and the second store hit "analysis blobs are immutable" (`put-words`, seen in the live re-run). A blob already stored for that revision now stands and the job succeeds.
- **The first message says where to look.** With full access it tells the agent to find files the human names with its own tools first, then hand gmclip absolute paths. The first live re-run (before this line) added the Movies videos but took "BB IDE assets" to mean them and never opened `~/Downloads/BB IDE Assets/`.
